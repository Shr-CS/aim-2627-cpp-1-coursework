# AIM 2627 C++ Assessment 01 — 实现说明

本文件记录 Q1–Q8 与挑战题 B1/B2 的实现思路、关键边界和复杂度，自补充的边界测试，以及开发中实际发现的一处缺陷。所有实现只改动 `src/main/A1_*.cpp` 中 `// BEGIN IMPLEMENTATION` 与 `// END IMPLEMENTATION` 之间的内容，固定接口、固定类型、公开测试与工具均未改动。本地边界测试放在 `local_tests/`，运行方式：

```bash
./local_tests/run.sh          # 编译并运行 local_tests/boundary_tests.cpp
```

公开自检可用 `cmake -S . -B build && cmake --build build && ctest --test-dir build`，或直接跑 `python3 tools/check.py . --output scores --require-core`。

## Q1 定点遥测规范化

**思路。** `ratio` 先处理 `max_hp<=0` 的无效情形返回 -1（此时不做除法），再把 `hp` 夹到 `[0,max_hp]`，最后 `hp*100/max_hp` 整数截断。`report` 先把 `battery` 夹到 `[0,100]` 并分出 OK/WARNING/LOW 三档，HP 字段在 `max_hp<=0` 时写 `INVALID`，否则复用 `ratio` 的结果，按 `ID=..;HP=..;BAT=..;STATE=..` 拼接。

**关键边界。** `hp<0` 归零、`hp>max_hp` 封顶 100；`max_hp=0` 与负 `max_hp` 都写 `INVALID` 而电量照常处理；`battery` 为 59/60、19/20 时先夹取再分档；10^12 量级参数下 `hp*100` 用 `long long` 保存，不溢出。

**复杂度。** O(1) 时间与额外空间。

## Q2 设备标签维护

**思路。** 先把逗号分隔文本拆成 `std::vector<std::string>`，再按 `edits` 顺序逐条处理：`from` 为空且 `to` 非空时追加；两者皆空不动；`from` 非空时线性查找**第一个完全相等**的标签，`to` 非空则替换、`to` 为空则删除该项，只处理首次命中。最后用逗号重新拼接，天然保证无首尾逗号和连续逗号。

**关键边界。** 完整字段匹配（`cam` 不命中 `cam2`、`camera`）；只改首次命中（`a,b,a` 只改第一个 `a`）；删除首/中/尾/唯一标签；先清空再追加不留前导逗号；`from==to` 也只处理一次；大小写敏感；每次编辑基于上一次结果重新查找，而不是缓存旧下标（变长改名后继续编辑）。

**复杂度。** 拆分与拼接 O(总长度)，每条编辑 O(标签数)，总计 O(总长度 + 编辑数×标签数)；输入上限 1000 字符、200 条编辑，远低于限制。

## Q3 窗口异常检测

**思路。** 滑动窗口：先算前 k 个元素的和，之后每推进一帧减去离开窗口的元素、加上进入窗口的元素，窗口和严格大于 `threshold` 时记录**右端下标**。`k<1` 或 `k>n` 直接返回空序列。

**关键边界。** 恰等于阈值不报警；负数求和也参与比较（`{-4,-3,-2}` 窗口和 -5 > -6 报警）；`k=1`、`k=n`、`k=0`、空输入；元素与阈值的极值组合下窗口和最大约 2×10^14，用 `long long` 保存，相邻元素差值也先提升到 `long long` 再参与累加，避免 int 减法边界问题。

**复杂度。** O(n) 时间（每个元素进出窗口各一次，不是 O(nk)），O(1) 额外工作空间（返回数组除外）。

## Q4 严格命令事务

**思路。** 每行一条命令、各自建 `std::istringstream`。先提取命令名，再按 `ADD x / SET x / RESET` 分支：参数用流提取读一个整数，随后**再尝试提取一个词**以拒绝多余字段（`SET 8 x`、`12x`、`5.0` 都会在这里被拒）；参数与候选结果都检查 `[-10^6,10^6]`。全部检查通过才写入累加器并 `accepted++`，否则只 `rejected++`，累加器保持原值。

**关键边界。** 空行/纯空白行拒绝；`add` 小写拒绝（大小写敏感）；`RESET x`、`RESET 0` 拒绝；缺参数、小数尾缀、超 `int64` 提取失败、参数越界、`ADD` 后候选越界（`SET 1000000` 后 `ADD 1`）全部整条拒绝；`ADD +2` 合法；首尾空白允许；`accepted+rejected` 恒等于行数。

**复杂度。** O(总字符数) 时间，O(1) 额外空间（每行的字符串流除外）。

## Q5 网格邻域风险图

**思路。** **先整图验证再计算**：空行数组直接返回空矩阵；否则要求每行等长、至少一列、只含 `.`/`#`，任一不满足抛 `std::invalid_argument`。然后逐格计算：障碍输出 -1，可通行格统计上、下、左、右四个方向的障碍数。

**关键边界。** `grid={}` 合法；`grid={""}` 零列非法；行长不一致、最后一行才出现非法字符都要抛异常且不返回部分结果；斜对角不计（`{"#.",".."}` 右下角的对角障碍不影响 (1,1)）；越界方向不算障碍（单格 `.` 输出 0 而不是 4）；单列地图照常算上下邻居。

**复杂度。** O(行数×列数) 时间，返回矩阵占同尺寸空间。

## Q6 目标优先级选择

**思路。** 一次遍历：先过滤 `visible && hp>0`，再用 `long long` 计算平方距离 `x²+y²` 与 `max_range²` 比较（含边界）。候选按三级比较 `(hp, 平方距离, id)` 取字典序最小者，返回其 id；无候选返回 -1。`max_range<0` 直接返回 -1。

**关键边界。** 射程边界包含（`x=10^6, max_range=10^6` 恰好入选，`x=y=10^6` 则 2×10^12 超界淘汰）；`hp=0`、负 hp、不可见目标淘汰；血量优先于距离（远处低血量目标胜出）；hp 与距离都相同时取较小 id，且与输入顺序无关；百万级坐标下平方用 `long long`，不溢出。

**复杂度。** O(n) 时间，O(1) 额外空间，不排序、不修改输入。

## Q7 热量与弹仓仿真

**思路。** 逐帧严格按规范顺序：**先冷却**（`heat-=cool`，负值归零），请求为 0 只冷却；请求为 1 时判 `ammo>0 && heat+shot_heat<=100`（等于 100 允许），成功则扣弹、加热量、`shots++`，失败只 `rejected++`。空请求序列不做任何冷却。

**关键边界。** 空序列返回原始 `ammo/heat`；无弹也先冷却再拒绝；`shot_heat=0` 合法（可以一直射到弹尽）；`heat+shot_heat` 恰为 100 允许、101 拒绝；拒绝不扣弹、不加热量；冷却后热量低于 0 归零；`shots/rejected/ammo/heat` 与逐帧记录互相守恒。

**复杂度。** O(帧数) 时间，O(1) 额外空间。

## Q8 遥测帧综合流水线

**思路。** 逐条处理：先做范围验证（`id∈[0,9999]` 且 `hp∈[-1000,1000]`），不合格计 `invalid` 且**不占编号**；合格再查 10000 格的标记表，已见计 `duplicate`，首次计 `valid` 并把 hp 夹到 `[0,100]` 累加进 `long long total_hp`。最后按编号顺序 0..9999 扫描标记表，天然得到升序 `ids`。

**关键边界。** 非法记录不占编号（`{1,-1001}` 之后 `{1,30}` 仍是首次合法）；已见编号的非法记录仍计 `invalid` 而不是 `duplicate`（`{1,20}` 后 `{1,-1001}` 是 invalid）；合法负血量夹取为 0，超上限夹到 100；id 端点 0/9999 合法、-1/10000 非法；`valid+duplicate+invalid` 恒等于输入条数、`valid==ids.size()`；空批次全 0；连续两次调用互不影响。

**复杂度。** O(帧数 + 10000) 时间，O(10000) 固定标记表空间（常数上限）。

## B1 挑战：有符号十进制解析

**思路。** 逐字符手工解析：可选单个 `+`/`-`，随后至少一位 ASCII 数字，任何其它字符立即失败。用 `long long` 累积数值，**每加一位之前**先判 `value > (limit-digit)/10` 直接拒绝，其中 `limit` 按符号取 2147483647 或 2147483648，因此不会先溢出再检查。失败一律 `return false` 且不写 `output`。不使用 `stoi/stol/stoll`、字符串流或 C 数字转换函数。

**关键边界。** 两个端点 `2147483647`、`-2147483648` 成功；越界一位（`2147483648`、`-2147483649`）失败并保留旧值；`+0`、`-0`、前导零合法；空串、单独符号、空白、小数点、双符号、尾随字符、`0x10`、1000 位数字串全部失败。

**复杂度。** O(字符串长度) 时间，O(1) 额外空间。

## B2 挑战：原地稳定压缩

**思路。** 写指针 `kept` 从 0 开始扫描数组，命中闭区间 `[low,high]` 的元素写到 `data[kept++]`。因为 `kept<=i` 恒成立，写入位置永远不会覆盖尚未读取的数据，且保留元素相对顺序不变（稳定）。`low>high` 或 `n==0` 直接返回 0 且不碰数组（`n==0` 时 `data` 可为 `nullptr`，不解引用）。

**关键边界。** 反向区间返回 0 且数组原样；全保留、全删除；重复值保留；`low==high` 单点区间；单元素数组；`nullptr,0`。

**复杂度。** O(n) 时间，O(1) 额外空间，无辅助容器。

## 自补充的边界测试

除公开用例外，在 `local_tests/boundary_tests.cpp` 补充了覆盖各题端点的用例（每题均有若干条，下面举 5 个代表性的）：

1. **Q8 非法记录不占编号 + 守恒**：`{{0,1000},{9999,-1000},{5,200},{5,10},{-1,30},{10000,30},{7,1001},{7,50}}` 期望 `valid=4, duplicate=1, invalid=3, total_hp=250, ids={0,5,7,9999}`。写这条时我一开始把 `{7,50}` 误判成 duplicate（以为 `{7,1001}` 已占住编号 7），断言失败后回头对照“非法记录不占编号”条款改正了期望值，实现本身是对的。
2. **Q4 事务边界**：`{"SET 1000000","ADD 1"}` → `{1000000,1,1}`（参数合法但候选越界）；`{"ADD -1000000","ADD -1"}` 验证下界对称；`{"ADD 5.0","ADD","RESET 0","ADD 12x","ADD 2147483648","ADD 99999999999999999999"}` 六种非法形态全部整条拒绝且互不影响。
3. **Q6 整数宽度与射程边界**：`{{1,1000000,0,5,true}}, max_range=1000000` 入选（平方距离恰为 10^12），`{{1,1000000,1000000,5,true}}` 淘汰（2×10^12 超界），确认平方和在 `long long` 中比较。
4. **Q7 热量端点**：`simulate(1,80,0,20,{1})` 恰到 100 允许射击，`simulate(1,80,0,21,{1})` 到 101 拒绝且不扣弹；`simulate(1,5,10,0,{0})` 冷却后热量归零。
5. **B1 输出保护与提前拒绝**：`"2147483648"`、`"-2147483649"`、1000 位 `'9'` 串均返回 false 且 `output` 保持调用前值；`"-2147483648"` 恰在下端点成功。

## 缺陷记录：`ratio` 从函数末尾“掉出去”（控制流缺返回值）

**现象。** Q1 第一版 `ratio` 把 `max_hp>0` 的处理写成最后的 `if` 块：

```cpp
long long ratio(long long hp, long long max_hp) {
    if(max_hp <= 0) return -1;
    if(hp <= 0) return 0;
    if(max_hp > 0){          // ← 只在 >0 时返回
        if(hp >= max_hp) return 100;
        else return int(hp*100/max_hp);
    }
    // ← 这里没有 return：若 max_hp > 0 不成立，函数走到结尾
}
```

**定位方法。** 开启 `-Wall` 编译时编译器直接给出 “control reaches end of non-void function”（函数可能从末尾掉出、没有返回值）警告。对照规范第 2/3 条才发现逻辑上`max_hp<=0` 分支已经提前 `return -1`，所以末尾的 `if (max_hp>0)` 恒为真——警告暴露的不是“取值不对”，而是控制流依赖隐含恒真条件，属于未定义行为隐患。另有 `int(hp*100/max_hp)` 的 `int` 强转会截断 `long long`，接口要求返回 `long long`，也一并改掉。

**修复。** 删掉恒真的 `if (max_hp > 0)` 包裹，让函数体在提前返回无效分支后按顺序收尾，所有路径都直达返回语句：

```cpp
long long ratio(long long hp, long long max_hp) {
    if(max_hp <= 0) return -1;
    if(hp <= 0) return 0;
    if(hp >= max_hp) return 100;
    return hp * 100 / max_hp;
}
```

修复后重新编译无警告，并用边界用例回归（`ratio(-5,100)==0`、`ratio(200,100)==100`、`ratio(10,0)==-1`、`ratio(2,3)==66`），`local_tests` 与 `tools/check.py` 全部通过。同类问题在后续题目中避免：函数体写成“前置校验 + 顺序收尾”的单出口结构，不把恒真条件当分支用。
